# 思源 MCP 工作流 Skill

面向思源笔记（SiYuan Note）的 MCP 优先工作流 Skill。

它不提供另一套思源 CLI、API 客户端、向量索引、向量数据库集成或凭据配置。这些属于已连接的 MCP 服务职责。Skill 负责定义让 Agent 稳定、安全地使用 MCP 的工作流程：工具边界与任务范围映射、编辑前检索、最小范围的块级修改、基于文档大纲的标题层级定位、写后验证，以及破坏性操作的显式确认。v0.3.0 的所有写入语义均在真实 MCP 服务上实测验证。

## 内容

- `skills/siyuan-mcp-workflows/SKILL.md`：可移植的 Skill 定义。

## 工作逻辑

1. 只读操作按需使用；写操作限定在任务映射表内；云同步、仓库回滚、集市安装、文件写入、全库导入导出默认禁用，必须由用户显式要求。
2. 搜索、读取并确认笔记本、文档或块的真实 ID 后，才进行编辑；三类 ID（笔记本/文档/块）互不通用。
3. 局部修改优先使用块级操作，避免删除并重建文档导致引用、属性和块 ID 丢失。
4. 向已写好的文档追加内容时，先读取标题大纲，再按语义关系定位：补充某节内容用其下一级标题，与既有小节并列用同级标题，同级标题层级保持一致；插入位置锚定到目标章节末尾，而非盲目追加到文档开头或结尾。
5. 每次写入后重新读取对应对象，确认内容、位置和元数据符合预期——不信任调用返回的成功消息。
6. 删除、批量修改、批量移动、批量替换标签与自动格式化前，先给出范围预览并等待明确确认。
7. 内部链接使用思源块引用；标签和属性优先通过 MCP 的专用工具维护。
8. 不自动同步、格式化或设置图标，这些会改变用户内容或偏好，必须由用户请求。

## 实测调用的关键语义

这些行为容易让 Agent 踩坑，均已写入 Skill 并附报错对照表：

- `document create` 必须同时传 `notebook` ID 和 `path`（hPath），只给标题会报 `path is required`；markdown 载荷不要以 `# 标题` 开头，否则文档内出现重复一级标题。
- `block update` 只替换一个块，多块载荷会静默丢弃后续内容且仍返回成功。
- `block insert` 只给 `parentID` 时插到父块顶部而非末尾；文档末尾追加用 `append`，中间定位用 `previousID`/`nextID`。
- `block append` 支持多块载荷，但只返回首块 ID，需重读验证。
- 大纲 depth 无法暴露标题层级错误（H2 后的 H4 仍是 depth 2），验证层级必须读 kramdown 的 `###` 标记。

## 安装

使用 Agent 的 Skill 安装机制安装此目录，然后开启新会话以刷新 Skill 索引。使用前需已配置并连接可用的 SiYuan MCP 服务。

也可以通过 `skills.sh` CLI 安装：

```bash
npx skills add 1001ww/siyuan-mcp-workflows --skill siyuan-mcp-workflows
```

## 适用范围

这是一个仅包含 Skill 的项目，假设你已拥有功能完整的思源 MCP 服务。它规范 MCP 的使用流程，不替代 MCP 服务本身。
